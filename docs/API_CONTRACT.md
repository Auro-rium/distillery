# API CONTRACT (server <-> frontend). Source of truth for both sides; change it here first.

Base path `/api`. JSON. Errors: `{"error": "<code>", "message": "<human text>"}` with proper HTTP status.
Every run/report object carries `dry_run: bool`; the UI MUST show a persistent banner "DRY RUN — fake models, numbers are NOT results"
when true, and "Recorded run · <recorded_at> · real Token Factory jobs" for replay bundles of real runs. Never show numbers without one of these labels.

## Read endpoints (public)
- `GET /api/health` -> `{ok: true, mode: "live"|"replay-only", version}`
- `GET /api/config` -> `{models: {planner: string|null, teacher: string|null, triage: string|null, student: string|null} (null = no model id configured on this server), thresholds: {ratio_lower_bound_min, mcnemar_alpha, bootstrap_resamples}, run_cap_usd, playground: {enabled, per_ip_per_hour, daily_cap_usd, spent_today_usd}}` (never secrets)
- `GET /api/runs` -> `[{run_id, dry_run, recorded: bool, recorded_at|null, status: "pending"|"running"|"complete"|"failed", decision: "PROMOTE"|"REJECT"|null, created_at}]`
- `GET /api/runs/{id}` -> `{run_id, dry_run, recorded, recorded_at, status, error|null, stages: [{name, status: "pending"|"running"|"done"|"failed", started_at: string|null, ended_at: string|null}], spend: {total_usd, cap_usd, by_model: {<model_id>: {usd, calls, input_tokens, output_tokens}}, finetune_usd_estimate|null, finetune_billed_usd|null, finetune_ceiling_usd|null}, sandbox: {operations: int|null, concurrency_peak: int|null}, verifier: {language: "python"|"sql", code: string|null, selftest: {accepted_gold: int, rejected_corruptions: int, failures: int}|null}}`
- `GET /api/runs/{id}/events` -> Server-Sent Events. `id:` monotonic int. Resume with the `Last-Event-ID` header OR the query parameter `?last_event_id=<int>` (same meaning; the query parameter wins if both are sent; invalid -> 0). `event:` one of `stage`, `spend`, `log`, `done`, plus `heartbeat` (liveness only: `data: {"ts": <unix seconds>}`, NO `id:` line so it never moves `Last-Event-ID`; consumers must not treat it as a stage/spend/log update; the UI uses it to reset its 30 s stale timer). `data:` JSON: `stage`: `{observed_at, at: string|null, name, status}`, `spend`: `{observed_at, ...same as spend above}`, `log`: `{observed_at, level, message}`, `done`: `{observed_at, status, decision}`. **`ts` no longer exists.** `observed_at` is when the server first noticed the change while polling (NOT when it happened). Only `stage.at` is an event time: the store's recorded timestamp of that transition (start time for `running`, end time for `done`/`failed`); null if unknown. Spend and log events carry no event time. Stored replay bundles may replay their own recorded `data` verbatim. `heartbeat` event every `heartbeat_s` (15 s) of silence while a run is active (replaces the old `: heartbeat` comment, which EventSource never shows to JS); it stops when the stream ends. Concurrency: at most `sse_max_streams` (default 32) streams server-wide and `sse_max_streams_per_ip` (default 4) per client address; beyond that `429 {error:"too_many_streams"}` with `Retry-After: 5`. The UI should fall back to polling `GET /api/runs/{id}` on 429.
- `GET /api/runs/{id}/report` -> the run's `report.json` verbatim (see `docs/fixtures/sample-dry-run-report.json` for the real shape) plus top-level `dry_run`, `recorded`, `recorded_at`. 404 `{error:"report_not_ready"}` until complete.
  Human held-out set (Gate B), added with `distillery run --human-set FILE` / `PipelineConfig.human_set_path` (the path itself is never in the report): top-level `decision_human: "PROMOTE"|"REJECT"|null` (null = no human set sealed; absent in older reports), `evaluation.human: {sha256, n, accuracy: {base, student, teacher}, unparseable, gate: <same shape as evaluation.gate, scored with the SAME thresholds>, examples, note}|null`, and `data.human: {sha256, file_sha256, n, dropped_exact_overlap: {train, dev, gate, total}, skeleton_in_train, counts: {questions, duplicates_dropped, kept, discarded, discarded_by_reason: {llm_error, no_sql, exec_error, empty, disagree}, confirmed, rejected, skipped, undecided}, db_sha256, question_file_sha256, teacher_model, note}|null`. `decision` stays Gate A (template gate, pipeline validation); `decision_human` is Gate B (the product claim). The two and the stress set are reported separately and never mixed. `note` discloses the selection bias (only teacher-solvable questions survive drafting).
- `GET /api/runs/{id}/tree` -> `{nodes: [{id, parent_id|null, label, round: int|null, hypothesis: string|null, data_delta: {added_rows: int, families: string[]}|null, dev_score: number|null, cost_usd: number|null, sandbox_image: string|null, selected: bool}]}` built from real sandbox lineage (`(uuid, parent_uuid, label)`) joined with per-round metrics. Never invent nodes.
- `GET /api/evidence` -> the curated proof ladder served verbatim from `deploy/evidence.json` (override the path with `DISTILLERY_EVIDENCE_FILE`): `{generated_at, commit, repo_url, proofs: [{id, title, verdict: "PASS"|"FAIL"|"PARTIAL", headline: {label, value, unit?}, metrics: [{label, value}], series?: [{step, train_loss, valid_loss}], evidence_path, evidence_url}], receipts: [Receipt]}`. Built by `scripts/build_evidence.py` from `docs/proofs/evidence/*.json` (numbers only, no sealed text); `evidence_url` is a commit-pinned GitHub blob URL. 404 `{error:"evidence_unavailable", message}` if the file is missing or unreadable. A `Receipt` is one checkable row per claim (the `/receipts` page): `{id, claim, status: "verified"|"pending"|"failed", verdict: "PASS"|"PARTIAL"|"FAIL"|null, value_display: string|null, artifact (repo path), permalink ({repo_url}/blob/{commit}/{artifact}), prereg: {commit, committed_at}|null, sealed_sha256: {name: sha256} (maybe empty), adapter_sha256|null, gate_inputs: {..}|null, ledger_total_usd|null}`. One receipt per proof (`verified` only when the proof's verdict is PASS; PARTIAL and FAIL are `failed`, `verdict` keeps the nuance), then the pre-registered claims `W-C1`, `W-C2`, `W-D`, `W-$`, `W-G`, `W-E2E`: `pending` (all of `value_display`, `verdict`, `prereg`, `adapter_sha256`, `gate_inputs`, `ledger_total_usd` null) until the evidence file named by `artifact` exists, then `verified`/`failed` from the keys in the `KEYS` table at the top of `scripts/build_evidence.py` (a present file that lacks a key stops the build). `W-G` is `verified` as a test (`tests/test_acme_wg.py`). `prereg` is null except where the evidence file records a pre-registration commit.
- `GET /api/runs/{id}/experiments` -> `{run_id, source: "store"|"bundle"|"unavailable", experiments: [{name, data, created_at?}]}`. Read-only, public like `/report`. Only rows named `finetune_job_*`, `serving_image*` or `expected_artifact*` are exposed. Local runs read `index.sqlite` (`source:"store"`); recorded replay runs read `experiments.json` from the bundle if present (`"bundle"`), else `[]` with `source:"unavailable"`. 404 `not_found` for an unknown run.
- `GET /api/runs/{id}/examples?kind=fixed|still_wrong|regressed|all&limit=20` -> `[{kind, task_id, family, heldout_class, question, gold_sql, base_sql, student_sql, teacher_sql, base_ok, student_ok, teacher_ok}]` (only after the run is complete; held-out items are revealed only post-evaluation). Source: `report.evaluation.examples` (top-level `report.examples` is a fallback). Filtering uses the stored `kind`. Core definitions, mutually exclusive: `fixed` = student ok AND base wrong; `regressed` = base ok AND student wrong; `still_wrong` = base wrong AND student wrong. Items both models solve are never examples. `all` = every stored example (fixed, then still_wrong, then regressed). **The list is a capped sample, not the full set**: the core keeps the first 20 items PER KIND in held-out order (deterministic, not random; at most 60 total). `limit` (1..200) only truncates further. Response headers: `X-Examples-Available: true|false` (false = report has no examples field, e.g. old reports/the sample fixture), `X-Examples-Cap-Per-Kind: 20`, and `X-Examples-Totals: {"fixed": int|null, "still_wrong": int|null, "regressed": int|null}` = counts over the WHOLE held-out set, so the UI can say "sample of N of M". `fixed` and `regressed` come from the recorded gate (`student_only_vs_base`, `base_only_vs_student`); `still_wrong` is derived from recorded `n`, `base_acc` and those two counts (null if it cannot be derived exactly). null = the report did not record it; the UI must then say "sample" without M.
- `GET /api/replay` -> list of replay bundles (same item shape as `/api/runs`). Default replay content until a real run is exported is the dry-run sample, labelled `dry_run: true`.

## Write endpoints
- `POST /api/runs` header `X-Admin-Token` (constant-time compare; missing/wrong -> 401/403; live runs also require body `approve_spend: true`) body `{pack: "sql", scale: "tiny"|"small"|"full", dry_run: bool, budget_usd?: number, run_id?: string}` -> `202 {run_id}`. `dry_run: true` needs no token but: anonymous callers may only use `scale: "tiny"` (else 403 `admin_token_required`; a valid `X-Admin-Token` lifts this, an invalid one -> 403), are rate-limited per IP (429 `rate_limited`), and get 429 `queue_full` (+`Retry-After`) when `max_pending_jobs` (default 5) runs are already queued or running. The per-IP key is the socket peer address; `X-Forwarded-For` is ignored unless the peer is listed in `DISTILLERY_TRUSTED_PROXIES` (comma-separated), in which case the right-most non-trusted hop is used. Runs execute in ONE background worker; a second live run while one is active -> 409. Cancel and server shutdown send SIGINT to the run's process group, then SIGKILL after `shutdown_grace_s` (default 30 s).
- `POST /api/runs/{id}/cancel` (admin) -> cancels provider jobs, `{status}`.
- `POST /api/playground` body `{question: string (<=500 chars)}` -> `{results: {teacher|base|student: {available: bool, reason|null, sql|null, verified: bool|null, rows_preview|null, error|null}}, cost_usd, note}`. Per-IP rate limit (429 with `Retry-After`) and the global daily $ cap (`503 {error:"demo_budget_exhausted"}` -> UI says "demo budget exhausted, see replay"). Models that cannot be served are `available:false` with an honest `reason` (e.g. "student serving path not deployed"); never fake a result. SQL is verified by executing it read-only against the demo DB and comparing with a gold answer only when the question matches a known task; otherwise `verified: null`.

## OpenAI-compatible gateway (`/v1`, public; spends only through caps)
"Change one base URL." Point any OpenAI SDK at `https://<host>/v1`. The gateway recognises the certified `acme-sql` skill and routes it through the certified router; everything else is passthrough. Errors on `/v1` use the OpenAI shape `{"error": {"message", "type", "param": null, "code"}, "distillery": {"request_id"}}` (not the `/api` shape above).
- `POST /v1/chat/completions` body: standard chat request (`model`, `messages`, optional `max_tokens`/`max_completion_tokens`, `temperature`, `top_p`, `stop`, `seed`). `stream: true` -> `400 stream_not_supported`; `tools`/`functions` -> `400 unsupported_field`. Body cap 64 KiB (`413`).
  - **Skill detection** (all must hold): `model` == the configured teacher id; `messages` is exactly `[system, user]`; the system content is byte-identical to `prompts.SYSTEM_PROMPT` (compared by sha256); the user content is exactly what `prompts.build_messages(question, ddl, role=...)` writes (`prompts.parse_user_content` inverts it). A schema longer than twice the demo DDL is not the skill either. Anything else is not the skill.
  - **Certified path**: nn_sim (the question is embedded through the upstream with the index's embedding model: priced, reserved against the daily cap, recorded as spend and added to the request's `cost_usd`; an unpriced or failing embedding sends the request to the teacher with the reason; the comparison with `embed_index_*.bin` is local) -> `router.precheck` (short-circuit to the teacher) -> student `generate_detailed` -> `extract_sql` -> run read-only on the demo DB when the DDL is the known schema (an unknown DDL is `exec_ok = 0`) -> `router.decide`. The student's SQL is served iff `served_by == "student"`; otherwise the teacher (same messages) answers. No loaded certificate: every request goes to the teacher with reason `not certified: all traffic goes to the teacher`.
  - **Response**: `chat.completion` (`choices[0].message.content` = the served answer; `usage` = the served call's usage: provider-measured for the teacher, completion tokens measured + prompt tokens estimated (chars/3) for the student), plus top-level `distillery`:
    `{served_by: "student"|"teacher"|"passthrough", skill: "acme-sql"|null, score: number|null, lambda: number|null, reason, short_circuit, sql: string|null, verified: bool (served SQL ran read-only with >= 1 row), columns: [..], rows: [[..]] (first <= 20), row_count, error|null, cost_usd (everything billed to this request: teacher call + the router's embedding), embed_cost_usd, teacher_cost_usd_counterfactual (null = unavailable), counterfactual_basis, latency_ms, request_id, usage_basis}`. Passthrough responses carry `{served_by:"passthrough", skill:null, cost_usd, latency_ms, request_id, max_tokens_applied, admin}`. `model` echoes the requested id; `distillery.served_by` is the truth.
  - **Headers** (ASCII): `x-distillery-served-by`, `-skill`, `-score`, `-lambda`, `-reason`, `-verified`, `-cost-usd`, `-latency-ms`, `-request-id` (the skill-only ones are absent on passthrough). `x-request-id` belongs to the access-log middleware.
  - **Passthrough**: only for models in the allowlist (default: the configured triage/Nano model; `DISTILLERY_GATEWAY_PASSTHROUGH_MODELS`), with `max_tokens` clamped to `DISTILLERY_GATEWAY_PASSTHROUGH_MAX_TOKENS` (default 256; also the default when none is sent). Any other model, or the teacher id with a non-skill prompt, needs the admin token (`X-Admin-Token`, or `Authorization: Bearer <admin token>`; a wrong `X-Admin-Token` is `403`) -> otherwise `403 model_not_allowed`. Admin passthrough is clamped to 4096 tokens. An unpriced model is `503 price_unavailable`; no upstream configured `503 upstream_unavailable`; a provider failure `502 upstream_error`.
  - **Limits** (all `429` + `Retry-After`): `rate_limited` (per address per hour, `DISTILLERY_GATEWAY_PER_IP_PER_HOUR`, default 30; admin exempt), `daily_budget_exhausted` (every teacher/passthrough call reserves against the playground's daily $ cap and is recorded as playground spend), `student_daily_cap` (`DISTILLERY_GATEWAY_STUDENT_DAILY_MAX`, default 200 sandbox student calls per UTC day, counted from the call log so a restart does not reset it).
  - Example: `curl -s $HOST/v1/chat/completions -H 'content-type: application/json' -d '{"model":"<teacher id>","messages":[{"role":"system","content":"<SYSTEM_PROMPT>"},{"role":"user","content":"Database schema:\n...\n\nQuestion: How many accounts are there?\n\n/no_think"}]}'` -> `{"id":"chatcmpl-...","object":"chat.completion","model":"<teacher id>","choices":[{"index":0,"message":{"role":"assistant","content":"SELECT COUNT(*) FROM accounts"},"finish_reason":"stop"}],"usage":{"prompt_tokens":1712,"completion_tokens":7,"total_tokens":1719},"distillery":{"served_by":"student","score":0.93,"lambda":0.81,"reason":"certified: confidence 0.93 \u2265 0.81","sql":"SELECT COUNT(*) FROM accounts","verified":true,"columns":["COUNT(*)"],"rows":[[240]],"row_count":1,"cost_usd":0.0,"teacher_cost_usd_counterfactual":0.0019,"latency_ms":412.0,"request_id":"req_..."}}`
- Call log: every call, served or refused, is a row in the store table `gateway_calls(id, created_at, day, request_id, ip_hash, model, skill, prompt_sha256, served_by, score, lambda, reason, input_tokens, output_tokens, cost_usd, teacher_cost_usd_counterfactual, counterfactual_basis, student_called, latency_ms, status, error)`; `status` is `ok|refused|error`, `served_by` is `student|teacher|passthrough|none`, `ip_hash` is a per-process salted hash (no raw addresses).
- `GET /api/gateway/status` -> `{certified, reason|null, lambda|null, coverage|null, selective_risk|null, alpha|null, delta|null, model_sha256|null, prereg_commit|null, similarity_index: bool, teacher_model, passthrough_models: [..], passthrough_max_tokens, student: "ok"|"unavailable"|"disabled"|..., drift: {enabled: bool, state: "CERTIFIED"|"TEACHER"|null}, today: {day, served_by: {student?, teacher?, passthrough?}, refused, student_calls, student_daily_max}}`. Router artifacts come from `DISTILLERY_ROUTER_DIR` (the `<run>/router/` directory: `model.json`, `cert.json`, one `embed_index_*.bin`); a certificate that pins a different model sha256 is ignored (`certified:false`, `reason` says why).
- `GET /api/gateway/savings` (computed server-side from `gateway_calls`; the UI only formats) -> `{window, requests, served_by: {student, teacher}, student_calls, refused, requests_in_savings, requests_excluded, total_spent_usd, actual_usd, teacher_only_usd, saved_usd, saved_pct|null, actual_display, teacher_only_display, saved_display, saved_pct_display|null, student_cost_basis, student_usd_per_1k|null, student_cost_usd|null, basis: {actual, teacher_only, saved}, passthrough_requests, passthrough_usd}`. Counts skill requests that were served (`status ok`); passthrough is reported apart. `teacher_only_usd` is the teacher's actual cost when it answered, else teacher price x (estimated prompt tokens + mean teacher output length: this gateway's logged teacher answers, else the measured mean of real teacher calls in pipeline runs). With no measured length the request is EXCLUDED from `actual_usd`/`teacher_only_usd`/`saved_*` (counted in `requests_excluded`; `requests_in_savings` are the rest); `total_spent_usd` is all spend on skill requests. `student_cost_basis` is `"pending H1"` with `student_usd_per_1k: null` until `deploy/serving_price.json` exists (`{"student_usd_per_1k": <USD per 1000 student invocations, served or deferred>, "source": "<how measured>", "as_of": "<date>"}`; override with `DISTILLERY_SERVING_PRICE_FILE`; a malformed file stops the server at startup); then it is `"measured: <source> (as of <date>)"` and `actual_usd` includes `student_calls / 1000 * student_usd_per_1k`. While pending, `saved_usd` excludes the student's serving cost and `basis.saved` says it is an upper bound.
- Demo agent: `scripts/acme_agent.py --base-url <url> --api-key <key>` runs `distillery.acme.AcmeAnalyst` (plain `openai` SDK) against any OpenAI-compatible URL; the only difference between Token Factory and the gateway is `--base-url`.
- `POST /api/acme/ask` body `{question: string (1..500 chars after trimming; unknown fields rejected)}` -> `{question, answer: {sql: string|null, columns: [..], rows: [[..]] (first <= 20), row_count, verified: bool (ran read-only with >= 1 row), error: string|null}, summary: string|null, summary_error: {code, message, status, retry_after: string|null}|null, summary_cost_usd: number|null, distillery: <the gateway's distillery object, verbatim, see /v1/chat/completions>, calls: [request_id, ...]}`. The Acme analyst run server-side for the website (the browser holds no key). The server makes the SAME two calls `distillery.acme.AcmeAnalyst` makes, as real `POST /v1/chat/completions` requests delivered in-process to this app through `httpx.ASGITransport`: (1) the `acme-sql` skill request (`prompts.build_messages(question, ddl, role="eval_teacher")`, model = the teacher id), so detection, routing (student vs teacher), per-address limit, daily caps and the `gateway_calls` row are exactly a customer's; (2) the served SQL is executed read-only on the demo database (the sandbox executor when configured, as the gateway does); (3) when it ran, a passthrough summary call on the triage model (`max_tokens` 128, one sentence). `calls` lists the `request_id` of each gateway call made, in order (rows of `gateway_calls`; `calls[0] == distillery.request_id`). The visitor's address (after the server's trusted-proxy rules) is the gateway's peer address, so the gateway limit counts the visitor, not the server; no request header (admin token included) is forwarded, so this endpoint is never admin. Each question costs up to two gateway requests against the per-address hourly limit. Errors use the `/api` shape `{error, message}` (+ `request_id` when the gateway made one): `400 invalid_json`, `413 payload_too_large` (8 KiB), `422 invalid_request`, and any refusal of the SQL call passes through with its gateway status and `Retry-After`: `429 rate_limited | daily_budget_exhausted | student_daily_cap`, `502 upstream_error`, `503 upstream_unavailable | price_unavailable | teacher_unavailable`. If only the summary call is refused or fails, the answer is still returned: `summary: null` and `summary_error` says why. `answer.error` is set (and `summary` skipped) when the model returned no SQL or the SQL failed to run.

### Drift guard (automatic rollback to teacher-only)
The certificate holds only for traffic like the calibration mix, so the gateway watches for a shift and rolls back by itself: state machine `CERTIFIED -> ROLLBACK -> TEACHER` (`ROLLBACK` is the transition event; the steady state is `TEACHER`, where every skill request goes to the teacher with reason `"rollback: drift detected → teacher (<detector>)"` and the student is not even invoked). The way back is only `recertify` with a NEW certificate. A rollback also queues a `redistill_queued` event (nothing re-distils automatically).
- Detectors, evaluated after each skill request the router decided (precheck short-circuits and certified-threshold decisions; infrastructure deferrals such as "student unavailable" and non-skill passthrough do not count): `deferral_rate` = the share of the last `window_w` requests served by the teacher is `>= tau` (exact comparison; only after `min_requests` requests); `audit_disagreement` = `>= audit_k` teacher disagreements among the last `audit_window_m` audited student answers. An audit re-asks the teacher after the answer was sent (selected deterministically by a hash of the request id, `audit_rate`), through the same daily-cap reservation as every paid call (a refused audit is skipped and counted, never a disagreement), and compares the two answers by executing both SQLs; its cost is added to the request's `gateway_calls.cost_usd`. A teacher SQL that does not run is inconclusive.
- Config (absent = guard DISABLED: the gateway never rolls back by itself): env `DISTILLERY_DRIFT_WINDOW` and `DISTILLERY_DRIFT_TAU` (required together) plus optional `DISTILLERY_DRIFT_AUDIT_RATE` (default 0 = no audits), `DISTILLERY_DRIFT_AUDIT_WINDOW` (50), `DISTILLERY_DRIFT_AUDIT_K` (5), `DISTILLERY_DRIFT_MIN_REQUESTS` (= window); or a `drift.json` with the same keys (`window_w, tau, audit_rate, audit_window_m, audit_k, min_requests`) in `DISTILLERY_ROUTER_DIR`. Env wins over the file; a malformed config stops the server. Calibrate `tau` with `scripts/drift_sim.py`.
- Persistence: every transition is a row in the store table `drift_events(id, created_at, state_from, state_to, kind, detector, details_json)` (`kind` is `rollback|teacher_only|redistill_queued|recertify`). At startup the state is restored from the last row: a restart in `TEACHER` stays in `TEACHER` (also if the config was removed: the params recorded in the rollback are kept), and a new `cert.json` on disk never recertifies by itself; a `cert.json` the deployment already rolled back from, put back on disk, is rolled back again (`detector: "revoked_certificate"`). The window and audit counters are in memory (a restart empties them).
- `GET /api/gateway/drift` (public, read-only) -> `{enabled, state: "CERTIFIED"|"TEACHER"|null, allows_student: bool|null, reason|null, detector|null, params: {window_w, tau, audit_rate, audit_window_m, audit_k, min_requests}|null, cert_sha256|null, rolled_back_cert_sha256: [..], window: {requests_seen, window_requests, window_deferred, deferral_share|null, audits_in_window, audit_disagreements, armed}|null, audits: {audits, inconclusive, skipped_cap, skipped_error, spent_usd}, events: [{id, created_at, state_from, state_to, kind, detector|null, details}] (newest first, at most 20), note}`. `cert_sha256` is the SHA-256 of the loaded `cert.json` bytes.
- `POST /api/gateway/drift/recertify` header `X-Admin-Token` (missing -> 401 `admin_token_required`, wrong or none configured -> 403 `forbidden`), body `{cert_sha256, prereg_commit}` (unknown fields -> 422). The operator first puts the new `model.json`/`cert.json` in the router dir; the endpoint re-reads them, and `cert_sha256` must equal the new `cert.json`'s SHA-256 and differ from every certificate this deployment rolled back from. -> `200 {state: "CERTIFIED", cert_sha256, prereg_commit, lambda, event}`; errors use the `/api` shape: `404 drift_disabled`, `409 not_rolled_back` (state is not `TEACHER`), `409 same_certificate`, `409 cert_mismatch` (names the sha it found), `409 not_certified` (the new cert has no threshold), `422 invalid_request`. Both windows restart empty; the call is written to the `audit` table.

## Human held-out set endpoints (admin only)
Offline workflow: `distillery draft-heldout --questions FILE` (teacher drafts gold SQL, k=3 at temperature 0.8, spends, admin token + `--i-approve-spend`), then `distillery confirm-heldout` (or the screen below), then `distillery confirm-heldout --finalize` writes `humanset/<sha8>/human_confirmed.json`, then `distillery run --human-set <that file>`. Both endpoints require `X-Admin-Token` (missing -> 401, wrong or no admin token configured on the server -> 403, so they are locked on a hosted service without one). They expose gold SQL and are never part of a replay bundle or `/api/replay`.
- `GET /api/humanset/drafts?set=<8 hex>` (`set` optional: the newest set) -> `{sets: string[], set, teacher_model, db_sha256, question_file_sha256, n_questions, discarded_by_reason: {llm_error, no_sql, exec_error, empty, disagree}, tally: {confirmed, rejected, skipped, undecided}, items: [{task_id, question, gold_sql, requires_order, preview: {columns, rows, row_count}, decision: "confirm"|"reject"|"skip"|null}]}`. Discarded questions are not served. 404 `not_found` when no set exists; 422 for a malformed `set`.
- `POST /api/humanset/decide` body `{set, task_id, decision: "confirm"|"reject"|"skip"}` (unknown fields rejected) -> `{decision, tally}`. Appends to the same `decisions.jsonl` the CLI uses (last decision per id wins). 422 for an unknown `task_id` or malformed `set`, 404 for an unknown set.

## Field nullability (never fabricated)
- `sandbox.operations`, `sandbox.concurrency_peak`: always null today; the core records no sandbox operation counts.
- `verifier.code`: always null; the SQL pack uses a fixed execution-match verifier, no authored code is stored. `verifier.selftest` is null until the self-test stage completed.
- stage `started_at`: set only while the stage is `running` (the store row is overwritten on completion); null for `done`/`failed` and for replay bundles. `ended_at`: set for `done`/`failed`, null while `running`/`pending`.
- `finetune_usd_estimate`: null when no finetune spend row exists; it is the sum of `finetune_billed_usd` (measured x price, `finetune` rows) and `finetune_ceiling_usd` (`finetune_ceiling` rows), each null when it has no rows. Tree `cost_usd`: always null (not recorded per round).

## Dry-run determinism
The worker runs the same CLI path and defaults as `python -m distillery run --dry-run` (no seed/round overrides). Fake model behaviour depends on the run id (via the adapter digest), so an API dry run with the default random-tag id (`dry-sql-tiny-<8 hex>`) can take a different number of rounds than the CLI's `dry-sql-tiny`; with an explicit `run_id: "dry-sql-tiny"` results are identical (tested). This is expected: dry numbers are not results.

## Frontend rules
Four screens: New run, Live run, Experiment tree, Report; plus Replay (default landing, public) and the Acme analyst (route `/playground`: a question box with examples, an answer card per question from `POST /api/acme/ask` showing Student (certified) or Teacher (deferred), the confidence score against lambda, the reason, SQL, verified rows, summary, cost and latency; a certificate strip from `GET /api/gateway/status`, which says "Not certified yet: all traffic goes to the teacher" when `certified` is false; and a savings counter from `GET /api/gateway/savings` that shows the server's `*_display` strings and `basis`, with "pending H1" for the student serving cost; and a read-only drift guard panel from `GET /api/gateway/drift`: state badge (CERTIFIED ok, ROLLBACK/TEACHER warn), the detector params as configured, the window deferral share as reported, the audit counters and the event log newest first, with "re-distill queued (not run)" for `redistill_queued` and "Drift guard not configured" when `enabled` is false; no admin action is in the UI), a public `/receipts` page (one row per `receipts` entry of `GET /api/evidence`: status badge VERIFIED / PARTLY MET / NOT MET / PENDING, the claim, the evidence's value, the commit-pinned artifact link, pre-registration commit, sealed-set and adapter hashes shortened with the full value in the title, gate inputs, ledger total; a pending claim reads "Pending: pre-registered, not yet scored", shows no number and links nothing), and an unlinked admin-only `/humanset` screen for confirming drafted gold SQL (plain, no polish). Dark/light via `prefers-color-scheme` + toggle. Responsive to 400 px. No new numbers computed in the UI beyond formatting: every number comes from the API.
